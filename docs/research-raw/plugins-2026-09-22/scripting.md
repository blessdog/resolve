# DaVinci Resolve / Fusion — the community scripting & extension layer (research, 2026-09-22)

Scope: things other people built that an automation-minded solo creator (already driving Resolve from Python, on Apple Silicon) can adopt instead of building. 33 web searches / fetches plus GitHub and GitLab API calls. Star counts and last-push dates are from the GitHub API on 2026-09-22. Anything not confirmed from a primary page is marked **UNVERIFIED**.

## 0. The four gates that decide everything below (read first)

Every row's "how an agent uses it" depends on which of these gates it sits behind. Free-vs-Studio is the discriminating axis, not Apple Silicon (everything here is Lua/Python/DCTL and platform-neutral unless flagged).

| Gate | What it blocks | Since | Source |
|---|---|---|---|
| **UIManager** (Fusion's Qt GUI API for scripts) | any script that draws a window: Reactor Classic's in-app GUI, Roger Magnusson's tools, Shaderfuse's installer, most WSL "Scripts/Comp" tools | Resolve **Free 19.1** (Studio unaffected) | Shaderfuse site; BMD forum t=213158; Reactor-Anywhere README ("Resolve Free v15–v19.0.3" was the last free range with advanced scripting) |
| **External scripting** (fuscript / Python from outside the app, `DaVinciResolveScript` import) | your existing Python driver | Studio-only (always); 21.1 press explicitly restates "advanced scripting requires Studio" | digitalproduction.com 21.1 article; redsharknews |
| **Free 21.1 Lua sandbox** | in the free edition, `.py` files in Workspace > Scripts are silently ignored; Lua keeps running but `io`, `os.execute`, `package`, `require`, `ffi`, `bmd.readfile/writefile`, `print` are nil/muted. `resolve`, `fusion`, timeline/media/render calls and `dofile()` still work | Resolve **Free 21.1** (Sept 2026) | xere.my journal 2026-09-14; AutoSubs Resolve-Integration README; saadk408/davinci-resolve-lua-mcp README |
| **Workflow Integration plugins** (Electron panels) + **native MCP server** | any panel-style tool; the built-in AI-assistant bridge | Studio-only (WI since 16; MCP new in 21.1) | BMD manual part4123; digitalproduction; redsharknews |

**Consequence for Fuses:** Fuses are compiled per-render by Fusion's own Lua/DCTL host, not by the Scripts menu. No source I found says Fuses broke in free 21.1 — but no source tests it either. Vonk Ultra's own docs claim support up to "Resolve (Free) v18–20.2". **Fuses on free Resolve 21.x: UNVERIFIED; on Studio 21.x: expected to work (Metal on Apple Silicon is a supported Fusion 21 backend).** Test one Fuse before adopting a collection.

Also new since 21.0/21.1 and relevant to "don't build it": **Krokodove is now a built-in component of Fusion inside Resolve (free and Studio) since 21.0**, with 25+ more tools in 21.1 (digitalproduction 2026-07-10; cgchannel 2026-09). And Resolve Studio 21.1 ships a **native MCP server** (File > Setup AI Assistants; Claude, Claude Code, Codex) plus **20 new scripting APIs** (multicam create/flatten, auto-align clips, add transitions, speed/fade get/set, audio normalize, render/keyboard/project-setting presets, Media Pool transcription with speaker timing, DCTL validate/encrypt, clone media). Python 2 is gone.

## Top picks for an automation-minded creator (Apple Silicon, already scripting Resolve from Python, music-driven cuts)

1. **Decide the edition first.** Everything panel-shaped (Workflow Integrations, Reactor Classic GUI, UIManager scripts, native MCP, external Python) is Studio-only, and free 21.1 also silently drops `.py` from the Scripts menu and sandboxes Lua (`io`/`os.execute`/`require` nil). If you are on Studio, all rows are open; if on free, your Python driver already doesn't work externally and the survivable paths are Lua-in-Scripts-menu (AutoSubs/saadk408 mailbox pattern), Fuses (UNVERIFIED on 21.1), and Reactor Standalone for installs.
2. **Use BMD's 21.1 additions before any third-party MCP**: native MCP server + 20 new APIs (multicam, auto-align, transitions, speed/fade, normalize, presets, transcription with speaker timing). Keep `samuelgursky/davinci-resolve-mcp` (3k★, 100% method coverage) as the fallback where the native server is thin, and `czukowski/fusionscript-stubs` for IDE typing rather than pydavinci (lagging).
3. **For data-driven Fusion, install Vonk Ultra via Reactor Standalone** (`brew install --cask kartaverse/reactor/reactor`) and have your Python emit JSON (beat times, band energies) that `vJSONFromFile` reads — this is the mechanism that keeps analysis in Python and rendering in Fusion. Add **Suck Less Audio (WAV)** for raw amplitude drives and **Krokodove's Beat modifier** (already built into 21) for tempo pulses. Vonk is documented only to 20.2 — test one node on 21 first.
4. **For generating comps from code without Fusion open, use FLPP** (`.comp`/`.setting` ↔ JSON) alongside pysion, and `fuscript -l py3` for headless execution on Studio. mrJohnHolt's expression library and CapitalEase give you easing/expression snippets as data.
5. **Adopt, don't port**: AutoSubs (4.2k★) for transcription/subtitles, Rembg-Fuse for matte pulls, Shaderfuse/KAS for procedural backgrounds, hos_HeatMap_Ultra to profile slow nodes. Skip VilleOlof/Toolbox (archived) and the legacy Frame.io integration (dead on V4).
6. **Not found, do not go looking again**: "Chetal", "Cyclone", Rob Ballard, Alex Fichera, "DaVinci Resolve Toolkit"/"resolve-toolbox" as named collections — no trace in Reactor's 711 atoms, GitHub, or web. Nearest real things are listed in the rows above.
